# Field robot — tomato picking simulation

A mobile robot that drives through a tomato field, finds ripe fruit with its
cameras, and picks it with a UR5e arm. Built on ROS 2 Jazzy and Gazebo
Harmonic.

Everything runs in simulation. The repository carries a Docker setup, so the
only thing needed on the host is Docker itself.

## What it does

- **Mobile base** — four-wheel skid-steer, driven over `/cmd_vel`, with a 2D
  lidar and an IMU
- **Manipulator** — UR5e from the official `ur_description` package, with a
  two-finger gripper, planned by MoveIt 2
- **Field** — rows of procedurally grown tomato plants; each fruit is its own
  model, attached to its plant by a joint that can be released, which is the
  simulation's stand-in for cutting a stem
- **Perception** — two detectors running the same node with different
  settings: the body camera scans at range to decide which plant is worth
  approaching, the wrist camera supplies the close-up position the grasp is
  actually built from
- **Picking** — choose a target, look, refine, approach, grasp, release from
  the plant, retreat along the same axis, drop, stow

## Quick start

```bash
git clone <repository-url>
cd field_robot_project
chmod +x docker/*.sh
./docker/run.sh          # first run: ~20-40 min, mostly downloads
./docker/shell.sh        # a terminal inside the container
cb                       # build the workspace
```

Then four terminals, each opened with `./docker/shell.sh`:

```bash
# 1 - simulation
ros2 launch field_robot simulation.launch.py world:=tomato_field

# 2 - motion planning (wait for Gazebo to finish opening)
ros2 launch field_robot moveit.launch.py

# 3 - the two detectors
ros2 launch field_robot perception.launch.py

# 4 - drive up to a row of plants
ros2 run teleop_twist_keyboard teleop_twist_keyboard
```

With a tomato 0.35–0.75 m from the arm's shoulder, in a fifth terminal:

```bash
ros2 run field_robot pick_tomato.py
ros2 run field_robot pick_tomato.py --ros-args -p loop:=true   # keep going
```

Full setup notes and troubleshooting: [DOCKER.md](DOCKER.md).

## Running without Docker

Needs Ubuntu 24.04 with ROS 2 Jazzy. The package list in the
[`Dockerfile`](Dockerfile) is the dependency list; install the same packages,
clone into a colcon workspace, and `colcon build --symlink-install`.

## Layout

```
field_robot/                    the robot, the world, perception, task logic
├── urdf/                       base, arm, gripper, cameras (xacro)
├── worlds/                     the generated tomato field
├── config/                     ROS<->Gazebo bridge, controllers, RViz
├── launch/                     simulation, MoveIt, perception
└── scripts/                    field generator, detector, picker, utilities

field_robot_moveit_config/      generated by the MoveIt Setup Assistant
```

## Generating a different field

```bash
cd src/field_robot_project/field_robot/scripts
python3 generate_field.py --output ../worlds/tomato_field.sdf \
        --rows 4 --plants-per-row 8
```

Useful options: `--row-spacing`, `--plant-spacing`, `--min-fruits`,
`--max-fruits`, `--unripe-ratio`, `--leaf-chance` (foliage that partly hides
the fruit, off by default), `--seed`.

## Handy commands

| | |
| --- | --- |
| `ros2 run field_robot stow_arm.py` | fold the arm away before driving |
| `ros2 run field_robot ik_probe.py` | diagnose "the arm cannot reach anything" |
| `ros2 run field_robot test_gripper.py` | open and close the gripper |
| `ros2 run rqt_image_view rqt_image_view /tomatoes/scan_debug` | what the body camera detects |
| `ros2 control list_controllers` | check the controllers are active |
| `pkill -f "gz sim"; pkill -f ros_gz` | clear a simulation left over from a previous run |

## Known gaps

- MoveIt does not see the plants: they have collision geometry in Gazebo but
  are not in the planning scene, so the arm passes through branches. Feeding
  `/front_camera/points` to an octomap would fix it, and is the next thing
  worth doing.
- Picked fruit is released at a coordinate with nothing underneath it, so it
  falls to the ground. A basket is waiting on the navigation step.
- Grasping is delicate, as it tends to be in simulation; small objects can
  slip out of the fingers.
- No autonomous navigation yet. Nav2 is installed in the image but unused.
